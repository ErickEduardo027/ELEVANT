# Guía de prueba completa del prototipo ELEVANT

## A. Preparación única

1. Copiar los dos parches a `C:\ELEVANT-PARCHES` y aplicarlos con sus instructivos.
2. Ejecutar desde la raíz:

```powershell
.\PREPARAR-PROTOTIPO.cmd
```

3. Obtener la IP de la PC:

```powershell
ipconfig
```

4. En `frontend\mobile-agent\.env`, colocar la IPv4 de la PC, por ejemplo:

```env
EXPO_PUBLIC_API_URL=http://192.168.1.6:4310
```

El teléfono y la PC deben estar en la misma red. Permitir Node.js y el puerto 4310 en el firewall si Windows lo solicita.

## B. Comenzar con instalación limpia

Cerrar el backend y ejecutar:

```powershell
.\RESTABLECER-DATOS-PROTOTIPO.cmd
```

El archivo anterior se conserva como respaldo. Luego iniciar todo:

```powershell
.\INICIAR-PROTOTIPO.cmd
```

Comprobar:

- Backend: `http://localhost:4310/health`
- Departamentos: `http://localhost:5173`
- Portal de aerolínea: `http://localhost:3000`
- Móvil: escanear el QR de Expo Go.

## D. Flujo completo de demostración

### 1. Gestión Humana

1. Iniciar sesión como Gestión Humana.
2. Registrar un empleado como **Agente de Rampa** con un correo nuevo.
3. Crear/habilitar su cuenta.
4. Registrar habilitación, carnet, turno y disponibilidad vigentes.
5. Anotar el correo. La contraseña móvil temporal es `Elevant2026!`.

Resultado esperado: el agente queda activo, habilitado y disponible para OCC.

### 2. Portal de aerolínea

1. Abrir `http://localhost:3000/login` y usar el acceso demostrativo.
2. Entrar a `Solicitudes`.
3. Crear una solicitud de afiliación o servicio con datos identificables.
4. Anotar la referencia y actualizar la consulta.

Resultado esperado: la solicitud aparece como pendiente y también llega a Contratos.

### 3. Contratos

1. Iniciar sesión como Contratos.
2. Abrir `Solicitudes`, localizar la referencia y pasarla a revisión.
3. Aprobarla.
4. Crear contrato temporal o permanente con vigencia actual.
5. Registrar al menos un servicio pactado y una tarifa.
6. Confirmar que el contrato queda activo.

Resultado esperado: OCC puede ver la aerolínea contratada y Finanzas recibe los datos contractuales.

### 4. Planificación OCC

1. Iniciar sesión como Administrador/OCC.
2. Abrir `Planificación operativa`.
3. Registrar un vuelo para la aerolínea con contrato activo.
4. Seleccionar el agente creado por Gestión Humana y los servicios pactados.
5. Asignar y enviar al móvil.
6. En monitoreo, colocar el vuelo en un estado operativo válido: **Arrived**, **Landed / Taxiing** o **Arrived / Gate Arrival**.

Resultado esperado: el vuelo aparece en la aplicación del agente y permite iniciar la atención.

### 5. Aplicación móvil

1. Iniciar sesión con el correo del agente y `Elevant2026!`.
2. Abrir el vuelo asignado e iniciar atención.
3. Completar todas las secciones del checklist.
4. Registrar una incidencia y evidencia para demostrar trazabilidad.
5. Finalizar la atención.
6. Esperar la sincronización automática; el estado debe indicar sincronizado y mostrar sus tiempos.

Resultado esperado: no quedan registros pendientes y OCC recibe el reporte.

### 6. Chat móvil ↔ OCC

1. Desde el móvil enviar un mensaje a OCC.
2. En OCC abrir `Chat interno` y entrar en la conversación del agente.
3. Responder.
4. Volver al móvil y esperar la consulta automática.

Resultado esperado: ambos mensajes aparecen en los dos dispositivos sin duplicarse.

### 7. Revisión OCC

1. Abrir `Revisión`.
2. Consultar checklist, horas, incidencia y evidencia.
3. Aprobar la operación. Como demostración alternativa, devolverla con observación y corregirla antes de aprobar.

Resultado esperado: la operación aprobada queda disponible para Finanzas.

### 8. Finanzas

1. Iniciar sesión como Finanzas.
2. Abrir `Servicios aprobados` y localizar la operación.
3. Confirmar/aplicar la tarifa contractual.
4. Generar y guardar la prefactura.
5. Aprobar y enviar la prefactura.
6. Registrar la conciliación/cobro.

Resultado esperado: el ciclo financiero cambia de borrador a enviado/conciliado.

### 9. Reportes y exportaciones

1. Abrir reportes en OCC, Contratos, Gestión Humana y Finanzas.
2. Confirmar que reflejan los datos recién creados.
3. Exportar al menos un PDF y un Excel `.xls`.
4. Abrir ambos archivos y verificar contenido.

### 10. Chat departamental y notificaciones

1. Enviar un mensaje de Contratos a Finanzas.
2. Iniciar sesión en Finanzas y comprobar recepción/lectura.
3. Revisar las campanas de notificaciones generadas durante el flujo.
4. Abrir y cerrar el panel de desarrollo desde su botón flotante; debe iniciar cerrado.

### 11. Persistencia

1. Cerrar únicamente la ventana del backend.
2. Volver a ejecutar `backend-prototipo\INICIAR-BACKEND.cmd`.
3. Recargar las páginas.

Resultado esperado: agente, solicitud, contrato, vuelo, operación, chat y prefactura continúan registrados.

## E. Validación automática final

Antes de presentar:

```powershell
.\PROBAR-PROTOTIPO.cmd
git status
```

`next-env.d.ts` puede cambiar al ejecutar Next.js. No se incluye en el commit:

```powershell
git restore frontend/public-web/next-env.d.ts
```

## F. Orden recomendado para la presentación

Mantener abiertas cuatro sesiones de navegador, una por departamento, usando perfiles o ventanas privadas distintas. Mostrar en este orden:

1. Solicitud de aerolínea.
2. Contrato.
3. Agente habilitado.
4. Planificación y asignación.
5. Operación móvil y chat.
6. Revisión OCC.
7. Prefactura y conciliación.
8. Reportes PDF/Excel.
9. Reinicio del backend para demostrar persistencia.
